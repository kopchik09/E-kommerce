# E-commerce: учебный проект интернет-магазина

Небольшой проект на Python, который моделирует товары, категории и заказы интернет-магазина. Проект покрыт тестами на `pytest`.

## Требования

- Python 3.9 или новее (в коде используется `dict[str, Any]`)
- pytest 7 или новее (для настройки `pythonpath` в `pytest.ini`)

## Структура проекта

```
project/
├── pytest.ini          # настройки pytest
├── src/
│   └── main.py         # классы товаров, категорий и заказов
└── tests/
    └── test_main.py    # тесты
```

## Классы

### `BaseProduct` (абстрактный)

Базовый класс товара. Содержит общее для всех товаров:

- атрибуты `name`, `description`, `quantity`;
- цену `price` со свойством-сеттером: нулевая и отрицательная цена отклоняется, а при понижении цены нужно подтверждение `y`;
- сложение через `+`: складывать можно только товары одного класса, иначе возникает `TypeError`.

Абстрактный метод `total_value` обязан реализовать каждый конкретный товар. Создать объект `BaseProduct` напрямую нельзя.

### `InitLoggerMixin`

Миксин, который при создании объекта печатает его класс и параметры:

```python
Product('Продукт1', 'Описание продукта', 1200, 10)
```

### `Product`

Конкретный товар. Использует миксин `InitLoggerMixin` и `BaseProduct`. Содержит:

- `new_product(data, products)`: создаёт товар из словаря. Если товар с таким именем уже есть в списке, увеличивает его количество и возвращает существующий объект;
- `total_value`: цена умножить на количество;
- `__str__`: строка вида `Iphone 15, 210000 руб. Остаток: 8 шт.`

### `Smartphone` и `LawnGrass`

Наследники `Product` с дополнительными атрибутами:

- `Smartphone`: `efficiency`, `model`, `memory`, `color`;
- `LawnGrass`: `country`, `germination_period`, `color`.

### `BaseEntity` (абстрактный)

Общий интерфейс для категорий и заказов: свойства `total_quantity` и `total_cost`.

### `Category`

Категория, которая хранит список товаров:

- при создании и в `add_product` проверяет, что объект является `Product` или его наследником, иначе `TypeError`;
- `products`: строка со всеми товарами;
- `total_quantity` и `total_cost`: суммарное количество и стоимость;
- счётчики `category_count` и `product_count` на уровне класса.

### `Order`

Заказ на один товар:

- `Order(product, quantity)`;
- проверяет тип товара, положительное целое количество и наличие на складе;
- итоговая стоимость фиксируется при создании, поэтому последующее изменение цены товара не меняет заказ.

## Пример использования

```python
from main import Category, Order, Product, Smartphone

phone = Smartphone("Iphone 15", "512GB, Gray space", 210000.0, 8, 98.2, "15", 512, "Gray space")
grass = LawnGrass("Газонная трава", "Элитная трава", 500.0, 20, "Россия", "7 дней", "Зеленый")

category = Category("Смартфоны", "Высокотехнологичные смартфоны", [phone])
category.add_product(Product("Xiaomi Redmi Note 11", "1024GB, Синий", 31000.0, 14))

print(category.products)
print(category.total_cost)

order = Order(phone, 2)
print(order)            # Заказ: Iphone 15, 2 шт., итого 420000.0 руб.
```

## Запуск программы

Запускай файл из папки `src`, чтобы импорты работали:

```bash
cd project/src
python main.py
```

Блок `if __name__ == '__main__':` создаёт три товара и категории, затем выводит их данные.

## Тесты

Тесты написаны на `pytest` и лежат в папке `tests/`.

### Установка pytest

```bash
pip install -U pytest
```

### Настройка

Файл `pytest.ini` в папке `project/`:

```ini
[pytest]
pythonpath = src
testpaths = tests
```

- `pythonpath = src` позволяет тестам импортировать `main.py` напрямую.
- `testpaths = tests` ограничивает поиск тестов папкой `tests/`.

### Запуск

Из папки `project/`:

```bash
pytest
```

Подробный вывод:

```bash
pytest -v
```

Если появляется `ModuleNotFoundError`, запусти через модуль Python:

```bash
python -m pytest
```

### Что покрывают тесты

- **Цена:** отказ при нулевой и отрицательной цене, подтверждение и отказ при понижении (через `monkeypatch` вместо реального ввода), повышение без подтверждения.
- **`new_product`:** объединение дубликатов по имени без учёта регистра и пробелов.
- **Наследование:** `Smartphone` и `LawnGrass` наследуют `Product`, атрибуты заданы правильно.
- **Абстрактные классы:** `BaseProduct` и `BaseEntity` нельзя создать напрямую, наследник без `total_value` нельзя создать.
- **Сложение:** товары одного класса складываются, разных классов и не товаров дают `TypeError`.
- **Миксин:** вывод при создании совпадает с `Product('Продукт1', 'Описание продукта', 1200, 10)`.
- **Категории:** проверка типов при создании и в `add_product`, итоговые количество и стоимость.
- **Заказы:** стоимость, фиксация цены после её изменения, ошибки на неверном товаре, количестве и нехватке на складе.

Счётчики `Category` сбрасываются перед каждым тестом фикстурой `autouse`, поэтому тесты не влияют друг на друга.

## Замечания

- В `print(len(category.products))` берётся длина строки, а не количество товаров. Если нужно количество, используй `total_quantity`.
- Миксин печатает только те аргументы, которые переданы в `Product.__init__`. Для `Smartphone` и `LawnGrass` в вывод попадают только четыре базовых параметра.
